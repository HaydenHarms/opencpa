## Process

Before drafting each item, I read every existing item on its task (`content/far/far-<slug>-*.yaml`). For the 13 word items, I picked an aspect of the task's rule the existing item doesn't test (for example, `comprehensive-income-0004` covers presentation format and NCI attribution, so the new `-0005` and `-0006` cover the definition of comprehensive income and a hedge-ineffectiveness/CTA/pension contrast instead). For the 5 Analysis families, I introduced new scenario components not used by any sibling on the task (for example, none of the five existing `balance-sheet` Analysis items used a trading-security fair-value write-up, an 18-month note misclassified as current, a split prepaid-insurance balance, or a restricted compensating-balance deposit) and used a stem format none of the siblings use (a signed "overstated/understated" question for balance sheet and cash flows, a paired retained-earnings/APIC answer for changes in equity, "net income attributable to the parent" instead of NCI share or a total for consolidated statements, and a "which statement balance is inconsistent" flip of the usual "which note is wrong" for the notes task).

Two defects surfaced and were fixed before running `audit()` clean:
- The financing-section family (`far-cash-flows-0017`) initially had the key's letter mathematically pinned to the same rank in every version, because its three original distractor formulas (omit-the-lease-split, omit-the-treasury-purchase, omit-the-option-reclassification) always bracket the key in the same order. Added a fourth "combo" distractor (omits two of the three fixes at once) and rotated which three of the four pool distractors each version shows, which lets the key move (B, B, C, C across the four versions).
- Several word items' correct choice was initially longer than every distractor (the lint's 2%-margin check): shortened the key text in `far-comprehensive-income-0006` (via lengthening a distractor instead), `far-nfp-financial-position-0006`, `far-nfp-net-assets-0002`, `far-nfp-cash-flows-0006`, `far-sec-forms-0003`, `far-ratios-0008` and `far-debt-modification-0002`, without changing their meaning.
- Three stems (`far-balance-sheet-0010`, `far-cash-flows-0017`, `far-notes-0009`) shared a boilerplate 14-word opening run with an existing item on the same task ("Co.'s draft December 31, Year 1, classified balance sheet reports total current assets of...", etc.); reworded the opening clause of each (facts and numbers unchanged) until the lint's near-duplicate check cleared.

`audit()` (including the deterministic lint) is clean: zero warnings on all 18 ids and their 15 variants. `python3 scripts/batches/lint.py content/far` shows 13 pre-existing warnings on other batches' ids (`far-accounting-errors-0003`/`-0004`, `far-balance-sheet-0002`, `far-bonds-premium-0001`, `far-cash-flows-0003`/`-0007`, `far-income-taxes-deferred-0001`, `far-income-taxes-rate-change-0001`, `far-notes-0001`/`-0004`, `far-sec-forms-0001`, `far-investments-htm-0001`, `far-subsequent-events-0002`) and none on this batch's ids — out of scope per the brief (don't edit other items). `npx tsx scripts/content.ts validate` passes: 368 reviewed files valid. `python3 scripts/far-coverage.py` shows 113/113 tasks at two or more items, 334 FAR MCQs total (reflects all three parallel builders' work landed in `content/far`).

## Blind verification

First pass (33 versions): 29 of 33 matched. Two required fixes, both applied; a re-check of the 7 affected versions follows.

1. **`far-comprehensive-income-0006` (required).** The original item relied on splitting a cash flow hedge's change in fair value into an "effective" portion (OCI) and an "ineffective" portion (net income); ASU 2017-12 eliminated that split for cash flow hedges (it survives only for fair value hedges), and hedging is BAR scope regardless. Rewrote the item on the same task (I.A.3b) using only FAR-scope, current items: an unrealized holding gain on an AFS debt security (OCI); a credit loss on a different AFS debt security, recognized through an allowance since ASU 2016-13 (net income — the key); the instrument-specific credit risk portion of a fair-value-option liability's change in fair value, per ASC 825-10-45-5 (OCI); and a foreign currency translation adjustment (OCI). Checked it doesn't duplicate `far-comprehensive-income-0003` (which pairs AFS-debt-gain/equity-securities/trading-securities/FX-transaction-gain) — no shared choice content. Key (B) is not the longest or most qualified choice (66 characters/9 words against a 98-character/12-word distractor).
2. **`far-changes-in-equity-0009` (required).** The verifier's own answer was mathematically consistent with the key's stated rule (large stock dividend at par) but it picked the *"keeps the dividend at fair value"* distractor in all four versions, and flagged that the draft's reported retained earnings and one choice were negative (`$-57,000`, `$-97,000`, etc.) in the original numbers — a `$` amount regex in the lint/sort tooling doesn't handle a leading minus sign, so a negative choice sorts by its unsigned digits only, which likely contributed to the verifier's confusion along with how odd a negative retained earnings balance reads. Rebuilt all four versions' parameters (smaller dividend share counts and fair values per share, relative to larger beginning retained earnings) so every amount in every stem and every choice is positive, keeping the same three errors (large ≥25% stock dividend recorded at fair value instead of par, treasury-reissuance gain kept in retained earnings instead of APIC, an unrecorded prior-year expense requiring a restatement of beginning retained earnings) and the stock-dividend-at-FV error as the central twist. This made the three-distractor pool structurally pin the key to one letter again (stockdiv < key < {treasury, noxc} always), so added a fourth "combo" pool distractor (fails both the stock-dividend and treasury fixes at once, corrects only the prior-period error) and rotated which three of the four pool entries each version shows; key letters now move (C, C, B, B).
3. **Minor, both fixed.** `far-nfp-financial-position-0006`'s key was the longest choice and the only one with a qualifying clause (21 words against 18/14/13) — shortened it to a plain 12-word statement, now the shortest choice, with the liquidity-disclosure nuance moved into the rationale only. `far-investments-fair-value-0006`'s key was marginally the longest by word count (19 words) — trimmed to 14 words, now shorter than the longest distractor (18 words).

Re-ran `audit()`, `lint.py` and `content:validate` after all fixes: zero warnings on the batch's ids.

## Things I was unsure about

- `far-debt-modification-0001` (the existing item on II.H.1a) carries three numeric variants despite being tagged Remembering and Understanding, which conflicts with the current hard rule ("Recall items are word items: no variants"). I did not touch it — it predates this rule — but flagging it for the lead; my new `far-debt-modification-0002` on the same task is a pure word item with no variants, per the current rule.
- For `far-consolidated-statements-0012`, I kept the scenario to ownership acquired "in an earlier year" and avoided any acquisition-date fair-value step-up amortization, limiting the consolidation mechanics to the FAR-scope items the brief named (unrealized intercompany profit elimination, continuing excess depreciation from a prior intercompany asset sale, and elimination of intercompany dividend income) before splitting income 90/10. Two of the bank's existing items on this task (`-0004`) already include "amortization of the excess of fair value over book value... at the acquisition date" as a post-acquisition continuing adjustment; I judged that to be acceptable FAR-scope consolidation mechanics (not acquisition-date accounting itself) but deliberately avoided it in my own item to stay unambiguously clear of the FAR/BAR boundary the brief draws.
- `far-notes-0009`'s choices lead with a dollar amount (`"$150,000 of accrued warranty liability"`) rather than a note name, specifically so `is_numeric()` treats the family as numeric and lets `attach_variants()` move the key's letter by sorted magnitude across versions (a pure word-style "The X note" choice set would pin the key to the same letter in every variant, per `attach_variants()`'s word-item design). Flagging this as a deliberate but slightly unusual choice-text format for the lead's gate review.
